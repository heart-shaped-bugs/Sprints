## Критические баги (блокирующие)

### БАГ №1 – Длительность беременности не сохраняется

**Описание**  
В методе `simulate_day()` каждый день вызывается `random.randint(21, 28)` для определения общей длительности беременности. Это приводит к тому, что беременность может длиться разное количество дней в зависимости от случайности при каждом вызове, а не от фиксированного значения, определённого в момент зачатия.

**Как тест поймал**  
Тест `test_pregnancy_duration` создаёт беременность, запоминает день начала, затем вызывает `simulate_day()` 30 раз и проверяет, что яйцо отложилось между 21 и 28 днями. Из-за того, что порог каждый раз пересчитывается, яйцо может отложиться в случайный день, выходящий за пределы ожидаемого диапазона (например, на 30-й день) – тест падает с `AssertionError`.

```python
# Пример
start = echidna.pregnancy_start_day
for _ in range(30):
    echidna.simulate_day()
# Ожидается: 21 <= days_to_egg <= 28
# Реальность: может быть 30, если random.randint дал 30
```

**Как исправить**  
В `start_pregnancy()` один раз сгенерировать `self.pregnancy_duration = random.randint(21, 28)`. В `simulate_day()` использовать это фиксированное значение для сравнения.

### БАГ №2 – Длительность в сумке не сохраняется

**Описание**  
Аналогично беременности, каждый день в `simulate_day()` вызывается `random.randint(50, 55)` для определения, сколько дней детёныш должен провести в сумке. Из-за этого детёныш может покинуть сумку в любой день в диапазоне 50–55, но не фиксированный заранее.

**Как тест поймал**  
Тест `test_pouch_duration` проверяет, что после 50–55 дней сумка становится пустой. Из-за плавающего порога результат недетерминирован – тест иногда падает, иногда проходит.

**Как исправить**  
При рождении детёныша (вылуплении) установить `self.pouch_duration = random.randint(50, 55)`. В `simulate_day()` использовать это значение.

## Баги в логике роста и голодания

### БАГ №3 – Вес детёныша зависит от веса матери

**Описание**  
В формуле роста детёныша в сумке используется `self.weight` (вес матери) вместо веса самого детёныша. Требование: вес детёныша растёт от начального 0,4–0,5 г до ~400 г по формуле `начальный_вес * (900) ^ (дни_в_сумке / 60)`. В коде написано `self.weight * (900 ** (self.pouch_days / 60))`, что даёт огромные числа (мать весит килограммы).

**Как тест поймал**  
Тест `test_baby_growth_in_pouch` вычисляет ожидаемый вес детёныша на 30-й день: `0.00045 * 900 ** (30/60) ≈ 0.00045 * 30 ≈ 0.0135 кг = 13.5 г`. Фактически получает `7.5 * 900 ** 0.5 ≈ 7.5 * 30 = 225 кг` – `AssertionError`.

**Как исправить**  
Ввести атрибут `self.baby_weight` (изначально 0.00045 кг). В `simulate_day()` обновлять:

```python
self.baby_weight = self.baby_weight * (900 ** (1/60))  # ежедневный рост
# или целиком по формуле
self.baby_weight = self.baby_weight_at_birth * (900 ** (self.pouch_days / 60))
```

### БАГ №4 – `independent_age_days` не сбрасывается при смерти детёныша

**Описание**  
Если детёныш умирает от голода (>15 дней без кормления), атрибут `independent_age_days` (счётчик возраста самостоятельной жизни) не обнуляется. При следующем размножении старые дни могут накладываться на нового детёныша.

**Как тест поймал**  
Тест `test_death_resets_independent_age` создаёт детёныша, доводит до голодной смерти, затем начинает новую беременность. При проверке `independent_age_days` обнаруживается ненулевое значение – тест падает.

**Как исправить**  
В методе, который обрабатывает смерть детёныша (например, `_kill_baby()`), добавить:

```python
self.independent_age_days = 0
```

### БАГ №5 – Мёртвая ехидна может начать беременность

**Описание**  
В методе `start_pregnancy()` есть проверка `if not self.alive: raise ...`, но порядок проверок может быть неверным (например, проверка `self.is_pregnant` стоит раньше). Или проверка есть, но в `simulate_day()` мёртвая ехидна продолжает обновлять беременность.

**Как тест поймал**  
Тест `test_dead_cannot_start_pregnancy` убивает ехидну (`echidna.alive = False`), затем вызывает `start_pregnancy()`. Ожидается исключение. Фактически беременность начинается – `AssertionError`.

**Как исправить**  
В начале `start_pregnancy()` добавить:

```python
if not self.alive:
    raise RuntimeError("Dead echidna cannot get pregnant")
```

В `simulate_day()` в самом начале:

```python
if not self.alive:
    return {"status": "dead"}
```

### БАГ №6 – Штраф за голодание применяется только один раз

**Описание**  
Требование: если прошло >10 дней без кормления – детёныш голодает (штраф), если >15 дней – погибает. В текущей реализации штраф применяется однократно в день превышения порога, а не каждый последующий день.

**Как тест поймал**  
Тест `test_starvation_penalty_every_day` создаёт ситуацию, когда `days_since_last_feed = 12`, проверяет наличие штрафа, затем вызывает `simulate_day()` (становится 13) – ожидается повторное применение штрафа. Фактически штраф не начисляется повторно, тест падает.

**Как исправить**  
В `simulate_day()` каждый день после инкремента `days_since_last_feed` проверять:

```python
if self.baby_in_hiding:
    self.days_since_last_feed += 1
    if self.days_since_last_feed > 10:
        self._apply_starvation_penalty()  # каждый день
    if self.days_since_last_feed > 15:
        self._kill_baby()
```

Метод `_apply_starvation_penalty()` может уменьшать вес или здоровье детёныша.
